# JUDGE 1

## RANKINGS
- **Proposal A: The Rack Unit** — 87
  Strongest structural fulfillment of the owner's #1 rule: the lane is PRE-BOUND to the module's teaching parameter on mount — zero taps, always the same screen position in every lab, so motor memory transfers perfectly and the pre-binding itself SIGNALS what the module teaches. Lowest idiom count of the four (one motor pattern: tap legend, ride fader), prose/mistakes/CheckQuestion stay inline in the well with the display pinned above (formative feedback answered with the referenced display visible), sticky trays preserve compare-many A/B, and the fixed stage never resizes during adjustment. Every cited precedent verified in-repo. Weakest element: strict one-lane purism — interacting parameters (freq AND Q, the core of the EQ curriculum) can never be adjusted with both visible, and 'banks' add a third navigation tier (bank tab → dock button → lane) for big modules like Playground, which is real extraneous load for a novice.
- **Proposal B: Meter Bridge** — 85
  Near-twin of A with three superior micro-decisions: group sheets let 2–3 INTERACTING params be co-visible (better for EQ's freq×Q lessons than A's one lane), sheets swap content in place (no close/reopen flicker when comparing params), and the 'console tape' framing — the rail as an always-legible readout of experiment state — is a genuinely good learning-science observation. Decks staying open on select preserves A/B, and the configure-vs-experiment justification for diverging from the tools popup is the right doctrine. Weakest elements: the hero fader is OPTIONAL — modules without one demote the primary parameter to one-tap-plus-sheet, so the owner's non-negotiable is a convention here, not a structural guarantee as in A; and compactHeight shrinks the display precisely while the student is adjusting, weakening effect readability at the worst moment.
- **Proposal C: StageDeck — Fixed Stage, Console Layers** — 71
  The strongest co-visibility guarantee (zero-scroll operating surface — the failure class is structurally unbuildable) and the best option-collection surface in the set: the persistent GridPicker deck gives 1-tap-per-trial A/B with the whole option set visible under a live stage. But it buys this by exiling the lesson: one 12px caption per deck, all explanation behind a READ overlay — for novices, interleaved explanation is the scaffold (guided instruction beats discovery), and splitting read/operate surfaces breaks the read→try→check loop. Checks become an opt-in LAST deck a student may never swipe to, with verdicts demoted to popups — a real hazard for the certificate-credit flow. Worst gesture pairing of the four: horizontal paging vs horizontal DragSliders means a navigation mis-swipe CORRUPTS the parameter under study — silent state changes teach wrong cause→effect models. Per-module deck curation is uncontrolled editorial variance across 60+ modules. The console-layers metaphor is thematic, not pedagogic — learning a desk-layer navigation scheme before learning absorption is extraneous load.
- **Proposal D: Faceplate — the pinned on-stage instrument** — 68
  Contains the single best pedagogical idea in the set — finger on the physics, already proven in-app at MultiBand — plus the best readout idea (the drag tag riding the finger) and the best a11y doctrine (Deck-completeness rule). But as the GLOBAL architecture it miscalibrates: OptionSheet pick-applies-and-CLOSES kills compare-many A/B (2 taps per trial, no visible tried-set) on the most common lab lesson pattern — including its own flagship Wave migration, where the taught parameter (material/absorption) isn't spatial, so D's signature advantage doesn't even apply there. The finger occludes the exact display region being changed. Handles trade first-30-seconds obviousness for every-session-after directness — backwards for a curriculum app where most modules are visited once or twice. The 2s afterglow steppers are a timed, disappearing control (novice-hostile); 9.5px deck labels violate MIN_FONT 12; and StageGlass+handles is the riskiest single build (rated L), with clustered-handle mis-grabs corrupting the experiment like C's mis-swipes.

## ADVICE
Build on A's spine: pinned stage + bezel readouts + inline scroll well (prose, mistakes, CheckQuestion stay in reading order with the display pinned above them) + bottom dock with a lane PRE-BOUND to the module's teaching parameter. That pre-binding is the one mechanism that makes the owner's #1 non-negotiable structural rather than conventional — keep it as a hard rule (every module declares initialParam; the kit refuses to render without one).

Graft from B (the highest-value grafts): (1) group sheets — replace A's banks with B's group chips so 2–3 INTERACTING params (freq+Q, attack+release) can be co-visible in one sheet; this fixes A's only real pedagogy gap and covers the EQ family properly; (2) sheet content swap-in-place when tapping another chip; (3) the 'console tape' doctrine — dock/rail values are the always-legible state of the experiment, document it as intent; (4) B's configure-vs-experiment language to justify sticky lab surfaces diverging from the tools' pick-closes popups.

Graft from C: the persistent full-grid picker as A's sticky-tray VARIANT for collections that ARE the lesson (wall materials, mic patterns) — 3-column grid, ≥44dp cells, 1-tap-apply-stay-open, whole option set visible while the stage reacts. Also C's observation that Mic Principles' 10 section chips collapse into one selector. Kill C's horizontal deck paging, caption-only prose, CheckDeck, and verdict popups entirely — reading and checks stay inline in the well.

Graft from D, scoped: on-glass handles ONLY where the parameter is spatial and precedented (MultiBand nodes, RoomScene region drags, an edge-grip for HPF cutoff) as stage enhancements inside A's frame — with D's Deck-completeness rule kept as a hard a11y invariant (every handle mirrored by a dock route). Adopt D's drag tag (in-glass value chip during any gesture — it retires GraphicTruth's 313px-distant activeBar). Kill D's timed afterglow steppers (put persistent ± nudge buttons in the sheet instead), kill pick-closes for lab collections, kill the 9.5px font carryover (all new components at MIN_FONT 12, as A/B/C commit).

Also kill: B's compactHeight shrink-during-adjust (keep A's fixed stage; constrain surface height instead), and any design where the check or verdict leaves the scroll flow.

Keep the consensus migration order — kit → Harmonograph (worst single-screen ratio, smallest surface) → LiveSpectrumEq via a host flag (worst inversion, live-mic stage) → WaveLayout mass conversion with Room Builder last as the stress test — with A's per-module opt-in flag as the safety mechanism, converting wave modules behind the flag one at a time despite the single-file adapter."

# JUDGE 2

## RANKINGS
- **The Rack Unit (Proposal A)** — 86
  Strongest element: the cleanest structural fix with the cleanest perf posture — stage and dock leave the ScrollView (MultiMeter pinned-sibling precedent, verified), stage size is chosen at mount (S/M/L) so the live Skia canvas is NEVER resized mid-interaction, and the persistent ParamLane gives zero-tap adjustment of the bound param with no overlay churn. Every cited primitive verified in-repo (DragSlider anchored-dx guts, SplMeter ctrlBar/PopupOpt extraction, ReadoutGrid {k,v,helpKey} contract, WaveLayout adapter). Migration mechanism (per-module rack flag + optional LabShell props) has the smallest blast radius of all four; deliberately defers the 5-host extraction rather than making it load-bearing. Enforces MIN_FONT 12 in new components. Honest cost sizing. Weakest element: the always-on dock costs ~118dp even on trivial modules, leaving a ~220dp well on 550dp Androids where CheckQuestion cards get cramped; and select-then-edit hides sliders behind buttons — the discoverability mitigations (pulse, amber state) are plausible but unproven. The lane's per-param taper/rebind animation is fiddly. Residual trap is small: tray zIndex/pointerEvents partitioning (backdrop dims well only, glass stays live) needs careful in-tree layout, but it is the tools' proven de-modalized pattern.
- **Meter Bridge (Proposal B)** — 80
  Strongest element: best-articulated component contract (ParamSpec grammar, sheet content swap-in-place, sheets-stay-open-for-A/B rationale, explicit a11y spec with focus management and liveRegion) plus the LabModuleHost extraction, which is real leverage across the 5 verified copy-pasted hosts. Same sound spine as A; hero fader keeps the teaching param at zero taps. Weakest element / the engineering trap: the compactHeight rule is load-bearing — its own 550dp arithmetic (250 bridge + 34 + 52 rail + 220 sheet = 556 > 550) forces the bridge to ANIMATE its height when a sheet opens, i.e. continuously resizing a live Skia canvas (surface reallocation) possibly with a live mic feeding it. 'Viz mostly accept a height prop' is true (verified) but accepting a height prop is not the same as cheap animated resize on old Androids — this is exactly the hitch class A avoids by fixing stage size at mount. Secondarily: more overlay state machinery than A (ControlSurfaceLayer, group sheets, back-chain, focus restore), and folding the host extraction into migration step 3 raises mid-migration blast radius versus A's per-module flag.
- **Faceplate (Proposal D)** — 68
  Strongest element: pedagogy and prior art — finger-on-the-physics via the verified MultiBand nearest-node grab, the drag tag generalizing MultiMeter's cursor chip, and the PopFader docked below the glass is the most faithful realization of the owner's 'popup fader' spitball; effort estimates are the most honest of the four (StageGlass rated L, 'the core bet'). Weakest element: global leverage is the illusion here. The shared code is the frame; the essence — handles — is bespoke per module (viewBox projection/inverse-projection callbacks, handle taxonomy, grab-radius tuning per viz), and half the estate's parameters have no spatial home (Q, absorption, material), so those fall back to the Deck anyway — meaning you build and maintain TWO idioms (handles + value-buttons), which cuts against 'one idiom, learned once.' A11y is the weakest of the four: a screen-reader mode that swaps the PanResponder for focusable proxies is real extra engineering that will regress, and Deck labels ship at 9.5px — a known MIN_FONT violation flagged rather than fixed. Three discoverability features (shimmer, HANDLES overlay, persisted flags) exist to fix a problem sliders never had. Per-device threshold tuning with a phone-testing owner makes iteration expensive.
- **StageDeck (Proposal C)** — 62
  Strongest element: the most rigorous vertical budget math (useStageBudget), the correct observation that the ScrollLock context needs a read-extension (verified: LabShell.tsx:165 carries only the setter), and genuinely thematic console-layer framing. Weakest element / the trap: the horizontal pager vs horizontal DragSlider conflict is waved off as 'identical, rotated 90°' — it is not. Today's proven system works because axes are orthogonal (native vertical scroller rarely steals during the scrollEnabled-update latency window when the drag is horizontal); a horizontal pager puts EVERY slider drag exactly on the native steal axis, and Android horizontal ScrollView interception can defeat onPanResponderTerminationRequest — the race the scroll-lock exists to paper over becomes constant instead of rare. Mitigable (pager scrollEnabled=false by default, rail-taps only) but unspecified. Second structural problem: the zero-scroll mandate converts a layout fix into a permanent per-module editorial tax ('deck curation is real design work per module' — their words), directly contradicting the solve-once brief, and it disturbs the most ratified surface area: CheckQuestion (29 files) rehoused into 2-line prompts + verdict popups, and all prose demoted behind a READ overlay — verbatim-preserved but a real presentation change to ratified copy. Heaviest pilot (7 bespoke EQ modules, rated L) = slowest first proof.

## ADVICE
Build on A's spine — it is B's spine with the two risky parts removed. Keep: pinned stage as a ScrollView sibling (MultiMeter precedent), bezel/in-glass readouts via the ReadoutGrid {k,v,helpKey} contract, bottom dock of SplMeter-anatomy value-buttons, persistent ParamLane (select-then-edit), sticky trays that dim only the well, per-module opt-in flag in the 5 hosts, WaveLayout as the 15-module adapter, Harmonograph as the pilot, and the hard rule that stage size is chosen at mount and NEVER animated. Graft from B: the ParamSpec-style typed grammar (it is the best-specified contract — use it to type A's DockParam), sheet/tray content swap-in-place when tapping another dock button (no close/reopen flicker), the sheets-stay-open-for-experiments rationale documented as intent, B's a11y spec (focus in/restore, accessibilityLiveRegion on the big value, adjustable role with increment/decrement on the lane), and the LabModuleHost extraction — but sequenced AFTER two hosts are converted via the flag, as cleanup, not as a migration dependency. Graft from C: useStageBudget as the one-place vertical arithmetic (A gestures at clamps; C actually computed them — steal the computation, drop the zero-scroll mandate), and the in-glass corner-cell positioning (tl/tr/bl/br) for displays that earn phase-2 in-canvas readouts. Graft from D: the drag tag / active-readout ghost driven by the ALREADY-EXISTING onDragActive plumbing on DragSlider and VerticalFader — it is nearly free, kills GraphicTruth's 313px-distant activeBar, and is the single highest-value/lowest-cost idea in any proposal; also keep D's principle that existing on-glass gestures (MultiBand nodes, RoomScene drag, Binaural) stay primary — A already sanctions this, D just says it best. Kill: C's horizontal deck paging entirely (same-axis native-interception race with DragSlider — the one proposal element that recreates the gesture war the pinning solves); B's animated compactHeight bridge resize (never resize a live Skia canvas — on 550dp, let the tray cover the well instead); D's full handle grammar as a v1 requirement (edge-grips/region handles become per-viz phase-2 upgrades where the display is intrinsically spatial, not a global obligation, avoiding the double idiom and the screen-reader proxy machinery); D's 9.5px deck labels (enforce MIN_FONT 12 as A/B/C do); and C's CheckQuestion rehousing + READ-overlay prose demotion (checks and ratified prose stay in the scroll well untouched — the owner's copy sensitivities make this the cheapest risk to simply not take)."

# JUDGE 3

## RANKINGS
- **A — The Rack Unit** — 87
  Strongest: the calmest, most hardware-true steady state — a persistent stage + bezel + lane + dock means the screen's anatomy never changes while a student wiggles-and-watches; nothing slides, dims, or resizes, which is exactly the rack-gear temperament of ToolsHub and the owner's visual bar. Select-then-edit (tap the legend, ride the fader) is authentic digital-console grammar (channel-select + assignable encoder) already proven in-repo (M11, Room Builder walls), and the sticky tray that dims only the well while the glass stays live is the single best A/B-learning move in any proposal. Typography discipline is explicit (new components at 12, tools' 9.5 called legacy, not copied). Weakest: one button skin carries four verbs — fader chips BIND the lane, ▸ chips open trays, toggles flip inline, actions fire — while the identical-looking tools ctrlBar button always opens a popup. A student who learned 'value-button = chooser' in the SPL meter taps ROOM W and gets a silent rebind; the ▸ glyph is a thin disambiguator at 12px. Secondary dings: ~118dp of fixed dock even on modules whose primary gesture is on-glass (the lane sits there bound to a second-string param), and banks + dock + lane stack three control rows on the densest modules — the bottom sandwich is where the elegance starts to strain.
- **B — Meter Bridge** — 83
  Strongest: the tightest literal grammar match with the tools section — chip → surface is exactly the ctrlBar → popup verb, the surfaceStyles extraction gives tools a convergence path back, and the one deviation (decks stay open for compare-many) is named and documented as intent rather than drift, which is precisely how a design language should fork. The hero fader is the cleanest possible answer to 'the taught parameter costs zero taps.' Weakest: it is the most motion-heavy and app-like of the four — every secondary adjustment raises and lowers a bottom sheet, the lesson body dims to 40% (or is fully covered on 550dp), and the bridge itself SHRINKS via compactHeight while a tall surface is open. The display you are supposed to be watching changing size as you open a control is a genuine design smell, and five stacked bands (bridge / hero / dimmed sliver / sheet / rail) mid-interaction reads busier than rack gear should. Bottom sheets are also the most generic mobile idiom on the menu — every app has them; a rack unit doesn't grow ephemeral drawers per knob. The hero fader is a special-case control outside the rail grammar (pedagogically motivated, but it's a second idiom). Net: best coherence-on-paper, second-best coherence-in-the-hand.
- **D — Faceplate** — 73
  Strongest: the single best idea in the field — handles ON the glass with a drag tag riding the finger, generalized from MultiBand's shipped PanResponder. 'Finger on the physics' is the purest execution of the owner's readouts-inside-the-display spitball, and the in-glass ReadoutRail has verified precedent (cornerReadouts, MultiMeter cursor chip). The deck-below-glass docking of popups is right. Weakest, and these hit the judging criteria directly: (1) it fails self-evidence by its own admission — a one-time shimmer, a dedicated ✋ HANDLES overlay mode, and a Deck-completeness fallback ARE a tutorial apparatus, needed because ◈/▐▓▓/⊕ glyphs carry no native affordance the way a slider does; (2) it deliberately ships the tools' 9.5px Oswald labels in NEW components and asks the owner to ratify a standing MIN_FONT exception — the only proposal that propagates the violation rather than retiring it; (3) the handle grammar applies unevenly — EQ curves and room scenes shine, but attack times, sample rates, and mix amounts have no spatial home and degenerate to deck+PopFader, so the system's signature idiom is present in a minority of modules and lab character varies (the exact thing 'one idiom, learned once' forbids); (4) afterglow steppers — controls that appear for 2s and vanish on a timer — are twitchy, gimmick-adjacent UI. Also the highest-risk core component (StageGlass rated L, 'the core bet').
- **C — StageDeck** — 66
  Strongest: 'reading may scroll, operating may not' is the crispest law articulated by any proposal, the vertical budget math is the most rigorous, and the layer-key rail is authentic digital-desk furniture with real curricular value. Weakest: it is the most clever and least elegant. The horizontal deck pager is a navigational grammar with zero precedent in the tools section — the primary interaction surface stops feeling like the same app. It rotates the codebase's most painful bug class (drag-vs-scroll, three generations of owner fixes plus the fresh e64265b slider-whip commit) onto the SAME axis as every horizontal DragSlider, in a 232dp deck that is mostly slider; capture-claim means pager swipes must start on slivers of padding while the neighbor-peek actively invites swiping. Exiling all prose to LEARN/READ overlays restructures pedagogy under cover of a layout fix — ratified copy is 'rehoused, not cut,' but relocation behind a mode switch strains the ratified-copy non-negotiable's spirit, and CheckQuestion (29 files) gets compressed with verdicts pushed into popups. Its own tradeoffs admit the frame can't absorb density without per-module editorial surgery ('a fourth readout, a sixth deck' has to go) and wastes space on simple modules — i.e., it breaks character at BOTH ends of the scale. The notice ticker is gimmick-adjacent. Piloting on EQ (7 bespoke modules, rated L) is the riskiest opening move proposed.

## ADVICE
Build on A's spine: pinned recessed-glass stage + bezel readouts + scroll well + persistent bottom dock with the shared ParamLane, tray anchored above the dock dimming only the well. That skeleton is structurally cause→effect-proof, hardware-calm, and made of verified extractions (ctrlBar, PopupOpt, DragSlider guts, ReadoutGrid contract). Keep A's pilot order (Harmonograph → LiveSpectrumEq → WaveLayout+Room Builder), which A and B independently converged on. Then graft: (1) from B, the discipline of NAMING the deviations — write the 'configure vs experiment' doctrine (tools popups pick-and-close; lab trays stay open for A/B) into the kit as documented intent, and extract surfaceStyles as the shared skin so the tools can converge back; also take B's sheet-content-swap-in-place polish for the tray and its group-sheet pattern for genuinely co-taught parameter pairs (freq+Q). (2) From D, the on-glass layer for the spatial modules only — MultiBand nodes, RoomScene source/listener, Binaural stage — plus the drag tag riding the finger (retiring GraphicTruth's 313px-distant activeBar) and in-glass corner readouts as the phase-2 bezel upgrade; A already sanctions stage-primary gestures, so this slots in without a new grammar. (3) From C, keep only the phrase 'reading may scroll, operating may not' as the kit's stated law, and its bank-naming discipline (SOURCE/TONE/FX) for A's dense-module bank tabs. Kill: C's horizontal deck pager and prose exile (same-axis gesture risk + pedagogy restructure), the notice ticker, CheckQuestion compression; D's handle-grammar-everywhere ambition, afterglow steppers, HANDLES tutorial overlay, and above all its 9.5px carryover — every new component renders at MIN_FONT 12, no ratified exceptions; B's compactHeight bridge-shrink (the display must never resize during an interaction) and the free-floating hero fader (A's lane pre-bound to initialParam achieves the same zero-tap goal inside one grammar). Finally, fix A's one real coherence crack before building: collapse its four button verbs to two, visually distinguished — fader chips carry a tiny lane glyph and bind; everything else carries ▸ and opens a tray; toggles and actions get a distinct non-value-button treatment so the value-button skin keeps exactly one meaning per surface, matching what the tools taught.
