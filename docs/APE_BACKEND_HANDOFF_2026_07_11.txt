F) URGENT -- glossary_full_v.common_mistakes is UNREADABLE by clients (crash)
   Selecting common_mistakes from public.glossary_full_v as anon/authenticated
   fails: ERROR 42501 "permission denied for function has_academy_access". The
   view's mask is  CASE WHEN has_academy_access(auth.uid()) THEN common_mistakes
   ELSE NULL END, and the querying role lacks EXECUTE on has_academy_access, so
   the whole row select 403s the moment common_mistakes is in the column list.
   Impact (pre-client-fix): "Could not load this topic" on Flashcards/Matching/
   FITB, and glossary term details stuck on "Loading..." for free users.
   Client workaround shipped (2026-07-11): base fields are read from base
   `glossary`; common_mistakes is fetched from glossary_full_v in a SEPARATE
   NON-FATAL query (failure -> null). So the app no longer crashes, BUT
   common_mistakes will be NULL for EVERYONE (incl. academy) until the backend
   fixes the grant.
   Backend fix required: GRANT EXECUTE ON FUNCTION has_academy_access(uuid) TO
   anon, authenticated;  (and confirm the function body is safe for a null uid --
   it already returns false for null, tested). Once granted, the client's
   non-fatal query will start returning real/masked values automatically -- no
   further client change needed.
   (Also note item B's earlier finding: base `glossary` now has column-level
   grants only, which breaks PostgREST embedding -- the client no longer embeds.)
