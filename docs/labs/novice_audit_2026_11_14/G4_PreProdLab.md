## ENVIRONMENT BLOCKER found while walking (shared browser, not the app's design)

Going back from Stage 1 the first time, my project had vanished and the lab showed the empty start screen; opening Stage 2 later showed "This project is not on this device. Production projects are saved on the phone that created them — open it there, or start a new one from the lab home." I checked the browser's saved data: the project key `ape:production:preprod:v1` is written and then removed within one to two seconds, and a throwaway probe key I set (`ape:g4probe`, removed by me afterwards) was also deleted within 1-2 s, even while my own tab was on a harness page. Something in ANOTHER tab of this shared browser (likely a full-app guest session running the guest wipe, which keeps only GUEST_KEEP keys) is clearing `ape:*` keys continuously. Effect on this audit: any screen that re-reads the project from storage can find nothing. Workaround used: create a fresh project and open the target stage within a fraction of a second (scripted tap sequence), then walk that stage by hand. Each stage below was walked this way on its own fresh project, so readiness numbers start from zero on each. The real app on one phone would not show this; the wording of the "not on this device" message is judged on its own merits below.

Wording note on that message (it can appear for real users, e.g. a project opened from another device's link): "saved on the phone that created them" is clear, but a beginner who has never used another phone will be confused; add "If you just created it here, go back to the lab home and open it again."

## Lab verdict · Audio Pre-Production (start + home + 6 stages + 6 exercises + packet walked; stages walked on fresh projects because of the shared-browser storage wipe)

**The beginner's journey.** The start is calm and the project home is well organized (NEXT OUTSTANDING is an excellent guide), but the first impression is a red "Not Ready for Production 0 / 100". Each stage is a long phone form (1,350-2,100 words, 13-33 questions) with exceptionally clear, human helper lines and the best feedback system in my six labs: every gap the learner creates or leaves is explained with a real-world consequence and a fix ("the first dead cable is found with the performers on stage"; "a mistake is a fire or an electrocution"). The weight is length and warnings: three caution boxes before some forms, every question with its own "Not applicable" button, and the "what's missing" list only at the very bottom. The exercises (broken plans to repair, with live checklists) are the most motivating part.

**3 biggest orientation problems**
1. Very long single-scroll stage forms with no visible end or sub-steps; the gap list sits at the bottom, far from the field that caused it.
2. Warning/legal boxes stacked at the top of stages (up to three) and 33 identical "Not applicable to this project" buttons per stage add noise before the first question.
3. Exercises send the learner into the ordinary stage screen with no reminder of the exercise goals; exercise 1's "one sentence" brief is never shown; counters like "0 required" and singular/plural slips confuse.

**3 best things**
1. WHAT THIS PLAN IS STILL MISSING: consequence + fix for every gap, updated live (and hard BLOCKED states for safety).
2. NEXT OUTSTANDING and the clickable WHAT'S LEFT in the packet — the app always knows the next useful step.
3. Exercises framed as "a plan that has already gone wrong, for you to repair", with ✓ lines that tick as you work.

**First 30 seconds (rewrite suggestion).** Start screen: "Plan a recording or a show before anyone presses record. Pick what you're making; we'll ask the questions a real producer asks, one stage at a time, and tell you what's still missing." Project home in neutral grey for a new project: "Stage 1 of your plan: Define the project · 17 short questions · Start with the project name ›". Inside a stage: show sub-steps (Brief · Scope · Creative) and keep the 'still missing' item next to its field.

Environment blocker summary: the shared browser kept deleting the app's saved data (`ape:*` keys) within 1-2 s, so screens that re-read the project often showed "This project is not on this device" or "THIS DEVICE COULD NOT SAVE YOUR LAST ANSWER". All findings above are from screens walked by hand on freshly created projects; nothing was blocked from being seen, but persistence across screens could not be judged.
