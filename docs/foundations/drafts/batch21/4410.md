Topic Foundations: Machine Learning for Music and Sound

Imagine a researcher who leaves a recorder in a forest for a month. Later, a program lists every bird it heard. Another program takes a finished song and returns only the voice. No person wrote step-by-step rules for these jobs. Each program was shown many examples and found the patterns itself. So how can a computer learn to recognize sound, and even make new sound?

A recording is a long list of air pressure values, but that list does not show patterns clearly. So it is usually changed into an image of its frequencies over time. The frequency bands are spaced the way hearing judges pitch, with more detail in the low frequencies. That image is called a mel spectrogram.

Next, a program must find patterns in that image. It has many simple units in layers, and each layer passes numbers to the next. Each connection has a strength that can change. This kind of program is called a neural network. Some designs move small pattern detectors across the image. Others process the sound in time order and keep information about earlier moments.

The strengths are set by training. The network often learns from a large collection of clips with correct labels. A score measures each error, and the strengths change a little to reduce it. A network trained on a huge collection can later be trained a little more for a new job.

Training also needs fair checking. If training continues too long, the network can memorize its examples and fail on new sound. That problem is called overfitting. So some clips are kept apart to check progress during training. Others are used only once, at the end. Those last clips are called the test set.

With fair testing, networks can do real recognition jobs. Some give a clip several labels, such as rain and a dog. Some also report when each sound starts and stops. A related job divides a finished song into separate parts, such as the voice and each instrument.

The same kind of network can also create new sound. One method starts from random noise and removes a little in each of many steps, until music remains. That method is called a diffusion model. Another turns sound into a series of code numbers and predicts the next code, one at a time. Often, a typed description guides the result. Whether a network labels sound or creates it, using the trained network is called inference. Smaller versions of a network can run on a phone, so the audio can stay on the device.

The flashcards explain each part: sound as numbers, how networks are built, trained and tested, their jobs with sound, and running them on small devices. By the end, you will know how these systems learn from examples, how their results are checked fairly, and what they can do with sound.
