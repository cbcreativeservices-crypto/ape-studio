Topic Foundations: Machine Learning for Music and Sound

Imagine a phone app that hears a bird and names it. Another program takes a finished song and returns only the voice. No person wrote the rules for these jobs. Each program was shown many examples and found the patterns itself. So how can a computer learn to recognize sound, and even make new sound?

A recording is already a long list of air pressure values, but that list does not show patterns clearly. So it is usually changed into an image of its frequencies over time. The frequency bands are spaced the way hearing judges pitch, with more detail in the low frequencies. That image is called a mel spectrogram.

Next, a program must find patterns in that image. That program is called a neural network. It has many simple units in layers, and each layer passes numbers to the next. Each connection has a strength that can change. Some designs move small pattern detectors across the image. Others process the sound in time order and keep information about earlier moments. Still others compare every moment with every other moment.

During training, the network often sees many clips with correct labels. A score measures each error, and the strengths change a little to reduce it. A network trained on a huge collection can later be adjusted for a new job. If training continues too long, the network can memorize its examples and fail on new sound. That problem is called overfitting. So some clips are kept separate to check progress during training, and others are used only once, at the end. Those last clips are called the test set. Clips from one recording session sound very alike, so they must all go in the training clips or all in the test set, never in both.

With fair testing, networks can do real sound recognition jobs. Some give a clip several labels, such as rain and a dog. Some also report when each sound starts and stops, a task called sound event detection. A related job divides a finished song into separate parts, such as the voice and each instrument.

The same kind of network can also create new sound. One method starts from random noise and removes a little in each of many steps, until music remains. That method is called a diffusion model. Another turns sound into a series of code numbers and predicts the next code, one at a time. A typed description guides the result.

The flashcards explain each part: how sound becomes numbers, how networks are built, trained and tested, and how they label, separate and create sound. They also explain how smaller networks run on a phone, so the audio stays on the device. By the end, you will know how these systems learn from examples, how their results are checked fairly, and what they can do with sound.
