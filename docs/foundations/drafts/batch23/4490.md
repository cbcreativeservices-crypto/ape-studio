Topic Foundations: Audio Coding and Codecs

Imagine a music album saved as raw numbers. That is often too much data to send quickly. So an encoder makes the data smaller, and a decoder rebuilds the sound. Together they form a codec. But how can sound lose most of its data and still sound almost the same?

The answer starts with hearing. A loud sound can hide quieter sounds near it in frequency. An encoder uses a model of hearing to find these hidden parts and uses little data for them. This method is called perceptual audio coding.

To use this, the encoder splits the sound into frequency bands, using a part called a filter bank. Each band's numbers are rounded, which saves data but adds a little noise. Each band gets a value, called a scalefactor, that sets how precisely its numbers are rounded. The encoder usually rounds less precisely where louder sound will hide the noise.

The encoder works on short blocks of sound. A sudden drum hit can spread rounding noise across its block, even before the hit. That faint noise is called pre-echo. Shorter blocks reduce it.

At low data rates, rounding alone is not enough. So the decoder can rebuild the high frequencies from the low ones and extra data. Because the left and right channels are often similar, an encoder can send one channel plus a little data about the differences. That method is called parametric stereo. Surround codecs can send sound shared by many channels only once.

Phone calls carry mostly speech, so they usually use a different method. Many speech codecs treat the voice as two parts: a sound source, and a filter that shapes it as the throat and mouth do. The encoder tests sources from a stored list and keeps the closest match to the voice. This idea is called code-excited linear prediction. When data is lost, the decoder often fills the gap with a similar sound. Calls and wireless headphones often need codecs built for low delay and little computing power.

Every device must read a codec's data the same way. So each standard combines some of these methods into sets called profiles, and describes how the data must be read. Coded data usually comes in units called audio frames. Each usually starts with a fixed pattern that helps the decoder find it, then settings for reading it. Not all codecs change the sound. Some use lossless coding, which keeps it exactly the same. Perceptual methods change it a little, so listeners compare coded sound with the original and give it a score. Computer models of hearing estimate that score.

The flashcards explain each method, the main types of codec, how coded data is organized, and how quality is judged. By the end, you will know how codecs make sound data smaller, why it still sounds almost the same, and how standards keep them compatible.
