Topic Foundations: Documentation and Diagrams

Imagine a technician called to a school hall to repair an old sound system. One speaker is silent, and nobody who built the system works there now. No records show where each cable goes. With good drawings and lists, the fault would be found quickly. This topic answers one question: how do professionals write down the details of a system, a show and a recording, so that others can use them later?

The first drawing shows how the signal travels. Each device is drawn as a box, and each connection is a line between boxes. The drawing shows the order of the parts, not their real positions. This drawing is called a block diagram. Similar drawings show a digital audio network, the paths in a recording session, or electrical power.

Other drawings show where equipment really sits: the front of a rack, the cables between the floors of a building, or the speakers in a ceiling. Each drawing uses standard symbols and a key that explains them. A box on the edge of each sheet names the job, the date and the version. That box is called the title block. Drawings change during a job, so each change is marked and recorded in a new version.

Drawings show paths, but a technician must find the real cable. So both ends of every cable are given the same name, matching the drawings. A table that lists every cable and where it starts and ends is called a cable schedule. Other lists say which microphone goes on each instrument, and which mixer channel it uses.

A touring show sends its paperwork before it arrives. Part of the performance contract lists the equipment that the performers need. That part is called a technical rider. Before the show day, the crew and the venue check every detail. Drawings show where the audience speakers and the performers' speakers go. Other lists give the wireless microphone frequencies, the cases to pack, and the order of songs.

When a show is recorded, the information is also stored inside the sound files. Each file can carry extra facts without changing the sound. That information is called recording metadata. Some facts are technical, such as the date, the place, an exact time stamp, the digital format, and the microphones and processors used. Others name the writers, performers, producers, engineers and owners. A name can be spelled in different ways, so codes are used too. A unique code for one recording is called a recording identifier. All these facts are checked before the files are delivered.

The flashcards explain each document: the drawings and how to read them, labels and connection lists, show paperwork, and the facts and codes inside recorded files. By the end, you will know which document answers which question, and why good documents let others build, repair and name the people who made the work later.
