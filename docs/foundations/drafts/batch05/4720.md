Topic Foundations: Audio Networking

In the core topic on networked audio, you learned that one thin network cable can carry many microphone channels. This topic looks at the network that carries them. Office networks can deliver an email a little late, but live sound cannot wait. So how does a network carry many live channels on time, without losing any?

It starts with how sound becomes data. The audio is cut into small parts, and each part is sent in a small block of data with an address. That block is called a packet. Each device has its own address, set by hand or given automatically by the network. Most devices follow one common set of rules for wired networks, called Ethernet.

The packets travel through cables. Copper cables work well over short distances. Glass cables that carry light reach much farther, and electrical noise does not affect them. Each connection between two devices also has a speed and a sending mode. Two connected devices usually agree on both without help. If they disagree on the mode, the connection can look fine while some of the audio is lost.

Cables join devices to a switch, a box that sends each packet toward its address. Usually every device has its own cable to a central switch. A backup cable between switches can form a loop. Then some messages travel around it again and again, and each switch copies them. This fast-growing number of messages, called a broadcast storm, can stop the whole network. For this reason, many switches can be set to turn off extra connections until a main one fails.

Next, which devices receive each channel's packets? Usually a device sends a separate copy to each receiver. When many receivers need the same sound, this uses a lot of capacity. Instead, a device can send one set of packets that any receiver can join. This is called multicast. The switches keep track of which receivers have joined, and send the packets only to them.

That tracking needs a switch you can set up and control, called a managed switch. When the network is busy, it sends timing and audio packets first. It can also keep audio apart from other data. Power-saving features are usually turned off, because leaving that mode adds delay.

Every step still adds a short delay: converting the sound, filling a packet, crossing each switch. Packets also arrive at slightly different times. So each receiver waits a fixed time before it plays. The total delay you allow for the whole system is called the latency budget.

The flashcards cover data and addresses, cables and speeds, central switches and loops, sending to one or many receivers, switch settings, and every kind of delay. By the end, you will know how a network carries live audio, and what keeps the sound complete and on time.
